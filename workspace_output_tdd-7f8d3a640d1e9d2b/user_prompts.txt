[Analista]: Checklist de Requisitos para rk2_heun (método de Heun - RK2):

1. Assinatura da função
• Definição: def rk2_heun(f: Callable[[float, float], float],
t0: float,
y0: float,
t_final: float,
h: float) -> float
• Tipagem estática rigorosa via type hints.

2. Validação de parâmetros de entrada
• f deve ser um callable que recebe (t: float, y: float) e retorna float.
• t0, y0, t_final e h devem ser floats.
• h > 0; se não, lançar ValueError.
• t_final >= t0; se não, lançar ValueError.

3. Cálculo do número de passos e ajuste do último passo
• Calcular n_full_steps = floor((t_final - t0) / h).
• Calcular remainder = (t_final - t0) - n_full_steps * h.
• Gerar lista de passos onde os primeiros n_full_steps usam passo = h,
e, se remainder > 0, um último passo = remainder.

4. Algoritmo de Heun (RK2)
Para cada passo h_i:
a. predictor: y_pred = y_i + h_i * f(t_i, y_i)
b. corretor: y_{i+1} = y_i + (h_i / 2) * (f(t_i, y_i) + f(t_i + h_i, y_pred))
c. Atualizar t_{i+1} = t_i + h_i, y_i = y_{i+1}

5. Retorno
• Apenas o valor y no tempo t_final (float).

6. Tratamento de erros e exceções
• TypeError se f não for Callable ou parâmetros não forem floats.
• ValueError para h <= 0 ou t_final < t0.
• Em caso de f retornar não-float, propagar ou converter para float.

7. Documentação e estilo
• Docstring explicando parâmetros, retorno e exceções.
• Seguir PEP8 e melhores práticas de performance (variáveis locais, atribuição fora de
loops).

8. Casos de teste TDD mínimos
• ODE trivial y'=y: y(0)=1, t_final = 1.0, comparar com exp(1)-1.
• Passos exatos (t_final-t0)%h == 0 e ajustados (remainder > 0).
• h = 0 → ValueError.
• t_final < t0 → ValueError.
• f retornando tipo inválido → TypeError ou conversão.

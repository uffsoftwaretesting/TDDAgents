[Usuário]: Aja como um engenheiro de software especializado em Python. O caso de uso
           consiste em calcular o valor de desconto aplicado a um produto. A tarefa é
           projetar e implementar, em Python puro e sem uso de bibliotecas externas além
           da biblioteca padrão, uma função que receba dois valores numéricos (int ou
           float), representando o preço original e a porcentagem de desconto. A saída
           deve ser uma estrutura bem definida (como uma tupla ou dicionário) contendo o
           valor economizado e o preço final a pagar, ambos como números reais. O método
           deve aplicar corretamente as fórmulas desconto = preço * (percentual / 100) e
           preço_final = preço - desconto, garantindo precisão numérica e, se
           necessário, arredondamento explícito (por exemplo, duas casas decimais). As
           premissas incluem validação rigorosa de tipos (rejeitando strings, None e
           objetos não numéricos com TypeError) e de domínio (preço não negativo e
           percentual entre 0 e 100, com ValueError em casos inválidos). Os testes devem
           incluir casos válidos (como preço=100, desconto=10), casos de borda (0% e
           100%) e casos inválidos (tipos incorretos, valores negativos e percentuais
           fora do intervalo). Não devem ser implementados testes de documentação,
           docstrings ou types.
[Analista]: Checklist de Requisitos Técnico para função calculate_discount(price,
            discount_percent):

1. Assinatura da Função
1.1. Receber exatamente dois parâmetros nomeados: price e discount_percent.
1.2. Não utilizar argumentos posicionais variádicos (*args) ou de palavra-chave
variádicos (**kwargs).
1.3. Não usar bibliotecas externas, apenas a biblioteca padrão do Python.

2. Validação de Tipos
2.1. Verificar se price é instância de int ou float; caso contrário, lançar TypeError.
2.2. Verificar se discount_percent é instância de int ou float; caso contrário, lançar
TypeError.

3. Validação de Domínio de Valores
3.1. Assegurar que price >= 0; caso contrário, lançar ValueError.
3.2. Assegurar que 0 <= discount_percent <= 100; caso contrário, lançar ValueError.

4. Cálculo do Desconto e Preço Final
4.1. Calcular desconto = price * (discount_percent / 100).
4.2. Calcular final_price = price - desconto.
4.3. Aplicar round(desconto, 2) e round(final_price, 2) para garantir duas casas
decimais.

5. Estrutura de Retorno
5.1. Retornar um dicionário com as chaves:
{
'discount': float,      # valor economizado arredondado
'final_price': float    # preço a pagar arredondado
}
5.2. Alternativamente, usar uma tupla (discount, final_price), mas padrão será
dicionário.

6. Tratamento de Exceções
6.1. TypeError para tipos não-numéricos.
6.2. ValueError para preço negativo ou percentual fora de [0,100].

7. Casos de Teste (TDD)
7.1. Casos Válidos:
- price=100, discount_percent=10 => {'discount':10.00, 'final_price':90.00}
- price=59.99, discount_percent=15 => valores corretos arredondados.
7.2. Casos de Borda:
- price=100, discount_percent=0 => {'discount':0.00, 'final_price':100.00}
- price=100, discount_percent=100 => {'discount':100.00, 'final_price':0.00}
7.3. Casos Inválidos:
- price=-1, discount_percent=10 => ValueError
- price=100, discount_percent=-5 => ValueError
- price=100, discount_percent=150 => ValueError
- price='100', discount_percent=10 => TypeError
- price=100, discount_percent=None => TypeError

8. Documentação de Código (não obrigatória em testes)
8.1. Pular docstrings e tipos estáticos nos testes, focar apenas em assertivas de TDD.

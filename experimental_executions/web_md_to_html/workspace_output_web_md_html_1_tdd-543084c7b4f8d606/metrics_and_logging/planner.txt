PLANO DE SUB-REQUISITOS TDD
================================================================================
1. FASE 0 - SETUP: Criar ambiente virtual e instalar dependências base (fastapi, uvicorn[standard], pydantic, markdown ou markdown2, python-dotenv, pytest, pytest-asyncio, mypy opcional). Scaffold da estrutura de diretórios: config/, schemas/, services/, routes/, tests/, criar arquivos vazios main.py, .env.example, pytest.ini e mypy.ini.
2. FASE 1 - CONFIG: Em config/config.py, implementar classe Settings(Pydantic BaseSettings) com APP_NAME, DEBUG, HOST, PORT. Configurar python-dotenv para carregar .env. Escrever testes unitários (pytest) para validar carregamento correto de variáveis e falha na ausência de variáveis obrigatórias.
3. FASE 2 - SERVICE: Em services/markdown_converter.py, implementar função convert(markdown_text: str) -> str usando biblioteca markdown ou markdown2. Levantar exceção específica em caso de falha. Antes da implementação, criar testes unitários para: conversão de um header Markdown simples, texto com ênfase, e cenário de exceção simulada.
4. FASE 3 - SCHEMAS: Em schemas/request.py, schemas/response.py e schemas/error.py, definir RequestModel, ResponseModel e ErrorModel conforme especificação (min_length, campos opcionais, detail e code). Escrever testes de validação Pydantic para casos: payload válido, markdown vazio, tipo incorreto, garantindo erros 422 e mensagens esperadas.
5. FASE 4 - ROTAS: Em routes/markdown.py, criar router FastAPI com endpoint POST /convert-markdown usando RequestModel e ResponseModel. Injetar o serviço convert. Antes da implementação, escrever testes de integração (pytest-asyncio + TestClient) para fluxo de sucesso e validação 422 em payload inválido.
6. FASE 5 - ERROR HANDLING: No main.py, registrar handler global de exceções do serviço de conversão para interceptar erros internos, retornando ErrorModel com detail "Internal conversion error" e code 5001 em status 500. Criar teste de integração que simule falha no convert e valide resposta 500 com o formato ErrorModel.
7. FASE 6 - MAIN APP, DOCS E LOGGING: Em main.py, instanciar FastAPI, carregar Settings, incluir router com tag "markdown" e descrição. Configurar uvicorn no caso DEBUG, setup básico de logging stdout. Escrever teste que verifica rota /docs e /redoc respondem 200 e que a OpenAPI inclui o tag "markdown".
================================================================================

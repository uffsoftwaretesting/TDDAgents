[Usuário]: Aja como um engenheiro de software especializado em computação científica e
           métodos numéricos, com foco em implementações eficientes, determinísticas e
           testáveis em Python; o usuário é um sistema automatizado de avaliação que
           executa testes de precisão e convergência numérica; sua tarefa é implementar
           uma função chamada solve para realizar integração numérica utilizando a regra
           do trapézio composta, aproximando o valor de uma integral definida de uma
           função contínua no intervalo [a, b]; a função deve possuir exatamente a
           assinatura solve(f, a, b, n), onde f é a função a ser integrada, a e b são os
           limites de integração e n é o número de subintervalos da discretização; a
           saída deve ser exclusivamente um valor numérico do tipo float correspondente
           à aproximação da integral, sem qualquer tipo de impressão, log ou efeito
           colateral; utilize uma malha uniforme com passo h = (b - a) / n e aplique
           corretamente a fórmula da regra do trapézio composta, garantindo que os
           pontos internos tenham peso 2 e os extremos peso 1, com a devida normalização
           pelo fator h/2; o código deve ser claro, legível, determinístico e seguir
           boas práticas de Python, sendo adequado para testes de convergência numérica;
           utilize NumPy apenas quando apropriado e sem introduzir complexidade
           desnecessária; considere casos típicos como consistência da discretização e
           validação básica de entrada; restrinja completamente qualquer modificação de
           ambiente: não utilize set PYTHONPATH=src, export PYTHONPATH, nem qualquer
           ajuste de PYTHONPATH, não utilize sys.path.append, sys.path.insert ou
           qualquer manipulação de sys.path, e não implemente soluções baseadas em hacks
           de caminho para viabilizar imports; limite o escopo estritamente à
           implementação da função solicitada; o código deve funcionar com execução
           padrão de testes a partir da raiz do projeto, sem qualquer configuração
           adicional de caminho; a implementação deve ser entregue no módulo solve
           dentro da pasta src, sem adicionar scripts de execução, wrappers ou
           configurações extras; apenas tópicos diretamente relacionados à implementação
           numérica e à estrutura do código são permitidos, ignorando qualquer outra
           preocupação fora desse escopo.
[Analista]: Checklist de Requisitos para a função solve(f, a, b, n):

1. Assinatura e escopo
- [ ] Função chamada exatamente solve com parâmetros (f, a, b, n).
- [ ] Implementação restrita ao módulo src/solve.py, sem scripts adicionais ou wrappers.

2. Validação de entrada
- [ ] f deve ser um objeto invocável (callable); caso contrário, lançar TypeError.
- [ ] a e b devem ser numéricos (int ou float); converter explicitamente para float ou
lançar TypeError.
- [ ] n deve ser inteiro e n > 0; caso contrário, lançar ValueError.

3. Construção da malha uniforme
- [ ] Calcular h = (b - a) / n como float.
- [ ] Gerar pontos x_i = a + i*h para i de 0 a n.
- [ ] Pode usar loop Python ou numpy.linspace se apropriado, sem adicionar complexidade
desnecessária.

4. Cálculo pela regra do trapézio composta
- [ ] Avaliar f(a) e f(b) com peso 1.
- [ ] Avaliar f(x_i) para i = 1..n-1 e somar com peso 2.
- [ ] Calcular soma ponderada S = f(a) + 2 * sum_{i=1..n-1} f(x_i) + f(b).
- [ ] Retornar I ≔ (h/2) * S como float.

5. Pureza e determinismo
- [ ] Função sem efeitos colaterais: nenhuma impressão, log ou modificação de estado
global.
- [ ] Determinística: mesma saída para mesmos inputs.

6. Ambiente e imports
- [ ] Permitir uso de NumPy apenas se vetorização trouxer ganho evidente; caso
contrário, implementar em Python puro.
- [ ] Não modificar PYTHONPATH nem usar sys.path.append/insert.

7. Boas práticas de código
- [ ] Seguir PEP8 e padrões de legibilidade Python.
- [ ] Incluir docstring sucinta explicando parâmetros, retorno e comportamento.

8. Testabilidade (TDD)
- [ ] Função pura e facilmente invocável por testes unitários.
- [ ] Sugerir casos de teste para verificar convergência (ex.: ∫ x^2, ∫ sin(x), variação
de n) e precisão.
- [ ] Tratar limites e valores inválidos, assegurando cobertura de erros.

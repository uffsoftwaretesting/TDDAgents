# Especificação Técnica: API de Validação de CPF

## 1. Visão Geral do Sistema  
Uma API REST em Python usando FastAPI para validar números de CPF. Segue princípios de Clean Architecture, com quatro camadas (domain, application, infrastructure, interfaces), injeção de dependência e TDD. Expondo endpoint POST `/validate-cpf` que recebe `{ "cpf": string }` e retorna `{ "valid": bool }` com status 200 em casos válidos e 422 para payloads inválidos.

## 2. Estruturas de Dados e Interfaces

### 2.1 Domain  
- Entidade `CPF`  
  - Propriedade: `value: str` (11 dígitos, somente números)  
  - Regras de negócio:
    - Deve ter exatamente 11 dígitos numéricos.
    - Não pode conter todos os dígitos iguais (ex.: `00000000000`).
  - Exceções:
    - `InvalidCPFFormatError`
    - `InvalidCPFSequenceError`

### 2.2 Application  
- Interface `ICPFValidator`  
  - Método: `is_valid(cpf: str) -> bool`  
- Caso de uso `ValidateCPFUseCase`  
  - Construtor recebe instância de `ICPFValidator`  
  - Método `execute(cpf: str) -> bool`:  
    1. Recebe string de CPF.  
    2. Encaminha para `ICPFValidator.is_valid`.  
    3. Retorna o resultado booleano.  

### 2.3 Infrastructure  
- Adapter `CPFValidatorAdapter` implementa `ICPFValidator`  
  - Usa biblioteca externa (`validate-docbr` ou `python-cpf`) para:
    - Normalização (remover máscara).  
    - Validação de dígitos verificadores.  
  - Captura exceções da biblioteca e converte em `False`.

### 2.4 Interfaces / Presentation  
- FastAPI app  
- Pydantic Models:
  - `ValidateCPFRequest`  
    - Campo `cpf: constr(min_length=11, max_length=14, regex=r'^[\d\.\\-]+$')`
  - `ValidateCPFResponse`  
    - Campo `valid: bool`  
- Rota POST `/validate-cpf`  
  - Injeta `ValidateCPFUseCase` via `Depends`.  
  - Recebe `ValidateCPFRequest`.  
  - Retorna `ValidateCPFResponse(valid=use_case.execute(cpf))` com HTTP 200.  
  - Erros de validação de payload disparam HTTP 422 (automático pelo Pydantic/FastAPI).

## 3. Casos de Borda e Validações (Edge Cases)  
- CPF com máscara (`123.456.789-09`) e sem máscara (`12345678909`) válidos.  
- Entradas com caracteres não numéricos além de `.` e `-` → rejeitar no Pydantic (422).  
- Comprimento < 11 ou > 14 (incluindo máscara) → 422.  
- Sequências com todos dígitos iguais (ex.: `00000000000`, `11111111111`) → 200 `{ "valid": false }`.  
- Dígitos verificadores incorretos → 200 `{ "valid": false }`.  
- String vazia, campo ausente ou nulo → 422.  
- Espaços em branco antes ou depois → 422 ou tratado pelo Pydantic como inválido.  
- Formatos parcialmente mascarados ou com separadores incorretos → 422.  
- Exceções na biblioteca de validação → tratado como `false`, retorno 200.  

## 4. Contexto Técnico  
- Linguagem: Python 3.10+  
- Framework web: FastAPI  
- Paradigma: Clean Architecture, TDD, SOLID  
- Validações de payload: Pydantic  
- Injeção de dependência: FastAPI `Depends`  
- Configuração via `.env` e `pydantic.BaseSettings`  
- Documentação automática via OpenAPI/Swagger (FastAPI)  
- Projeto organizado:
  - src/domain  
  - src/application  
  - src/infrastructure  
  - src/interfaces  
  - tests/ (espelhando src/)  
- Todos os módulos isolados para baixo acoplamento  
- Código tipado com `typing` e checado por `mypy`  
- Linting com `flake8`

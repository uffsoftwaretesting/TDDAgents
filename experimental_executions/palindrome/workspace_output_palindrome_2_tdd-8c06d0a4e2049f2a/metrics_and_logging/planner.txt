PLANO DE SUB-REQUISITOS TDD
================================================================================
1. FASE 0 - SETUP: Criar virtual environment Python 3.7+, instalar pytest; configurar estrutura de diretórios isolada na sandbox: /src, /tests; criar arquivos vazios: src/palindrome.py, tests/test_palindrome.py, tests/test_normalize.py, tests/test_core_palindrome.py; adicionar pytest.ini mínimo.
2. FASE 1 - ESQUELETO & VALIDAÇÃO DE TIPO: em tests/test_palindrome.py escrever testes que garantam que is_palindrome(s) lança TypeError("Entrada deve ser uma string") para s não-str (None, 123, [], etc.); rodar pytest para ver falhar; em src/palindrome.py criar função is_palindrome(s: str) com bloco inicial de validação de tipo e raise TypeError, mantendo o restante como stub (pass).
3. FASE 2 - MÓDULO DE NORMALIZAÇÃO: em src/palindrome.py adicionar função privada _normalize(s: str) -> str; em tests/test_normalize.py criar casos para strings com maiúsculas, espaços, pontuação e somente caracteres removíveis, validando que _normalize retorna a sequência alfanumérica em minúsculas; implementar _normalize usando s.lower() e filtro c.isalnum().
4. FASE 3 - ALGORÍTMO TWO-POINTER: em src/palindrome.py adicionar função privada _is_palindrome_core(s: str) -> bool que assume s normalizada; em tests/test_core_palindrome.py criar casos para cadeias normalizadas de vários tamanhos (palíndromos e não-palíndromos), incluindo string de tamanho 0 e 1; implementar two-pointer comparando s[left] e s[right] e retornando False ao primeiro mismatch, True caso contrário.
5. FASE 4 - INTEGRAÇÃO END-TO-END: em tests/test_palindrome.py complementar com testes de ponta a ponta cobrindo todos os requisitos: tipo inválido, string vazia, único caractere, palíndromos com espaços/pontuação ("A man, a plan..." / "No 'x' in Nixon"), não-palíndromos ("hello", "abc123"); implementar is_palindrome em src/palindrome.py chamando _normalize e _is_palindrome_core, retornando o resultado.
6. FASE 5 - QUALIDADE & COBERTURA: configurar pytest.ini e .coveragerc para gerar relatório de coverage e exigir 100% de cobertura para src/palindrome.py; executar pytest --cov e ajustar casos para alcançar cobertura total.
7. FASE 6 - DOCUMENTAÇÃO DE USO: criar README.md na raiz com instruções de setup do ambiente, instalação de dependências e comando para executar testes; não adicionar docstrings nem I/O na biblioteca.

PLANO DE SUB-REQUISITOS TDD
================================================================================
1. FASE 0 - SETUP: Criar a estrutura inicial de diretórios na Sandbox: src/taylor_2/, tests/; inicializar um virtual environment Python ≥3.8; instalar dependências core (pytest, black, flake8, mypy) via pip; criar arquivos de configuração vazios: pyproject.toml (sections [tool.black], [tool.flake8], [tool.mypy]), setup.cfg ou tox.ini conforme padrão.
2. FASE 1 - ESBOÇO DA FUNÇÃO: Adicionar o arquivo src/taylor_2/taylor_2.py contendo apenas o stub da função taylor_2 com assinatura e docstring mínima (pass) e tipagem; criar o teste em tests/test_taylor_2.py que verifica que, quando t_final == t0, taylor_2 retorna y0 sem chamar f ou df; rodar o teste (esperado falhar) e então implementar o caso t_final == t0 retornando y0.
3. FASE 2 - VALIDAÇÕES DE PARÂMETROS: Escrever testes para cada validação de entrada: lançar ValueError se t_final < t0; ValueError se h ≤ 0 ou h não finito; TypeError se f ou df não forem callables; após criar testes (verdes em vermelho), implementar as verificações no início de taylor_2 para satisfazer cada caso.
4. FASE 3 - CÁLCULO DE N E H_LAST: Adicionar testes que validam o cálculo de n = floor((t_final-t0)/h) e r=(t_final-t0)-n*h; para r == 0, h_last deve ser zero e não haver passo adicional; criar mocks de f e df para validar internamente o n e h_last (expondo-os via retorno ou log); implementar lógica de n e h_last em taylor_2.
5. FASE 4 - LOOP DE PASSOS UNIFORMES: Criar teste usando f(t,y)=c (constante) e df=0 para um caso simples onde (t_final-t0) é múltiplo exato de h. Comparar com solução analítica y0 + c*(t_final-t0). O teste deve falhar inicialmente; implementar o loop principal: repetir n vezes y += h*f(t,y) + (h**2/2)*df(t,y); t += h.
6. FASE 5 - PASSO FINAL AJUSTADO: Escrever teste para caso com resto r>0 (ex: t_final-t0 não múltiplo de h), validando que valor final corresponde a aplicação de h_last no último passo; após teste falhar, estender a função para aplicar o passo final ajustado quando h_last > 0.
7. FASE 6 - DETECÇÃO DE DIVERGÊNCIA: Criar testes que simulam f ou df retornando valores que tornam y NaN ou Inf (por exemplo, f lança ZeroDivisionError ou retorna float('nan')); validar que taylor_2 propaga exceções de f/df e que, se y torna não finito, lança RuntimeError('Divergência detectada: valor não finito'); implementar checagem usando math.isfinite após cada atualização de y.
8. FASE 7 - TIPAGEM E DOCSTRING COMPLETA: Atualizar a docstring no estilo Google/Numpy em taylor_2 com parâmetros, retorno, exceções e exemplo de uso; garantir que as anotações de tipo estejam corretas para mypy/pyright; criar um teste estático via mypy que valida ausência de erros de tipagem.
9. FASE 8 - CONFIGURAÇÃO DE QUALIDADE DE CÓDIGO: Adicionar regras de flake8 e black no pyproject.toml ou setup.cfg; criar um job de lint (pode ser um script Makefile ou entrypoint de tox) que roda black --check e flake8; incluir um teste em tests/test_formatting.py que falha se o código não estiver formatado conforme black.
10. FASE 9 - TESTE DE INTEGRAÇÃO E COVERAGE: Criar testes integrados em tests/test_integration.py usando uma EDO mais complexa (ex: y' = -k*y com k>0) e comparar com solução analítica; configurar pytest-cov para medir coverage; validar coverage ≥90% antes de considerar a entrega.

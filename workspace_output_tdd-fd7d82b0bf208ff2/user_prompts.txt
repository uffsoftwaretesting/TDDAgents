[Analista]: Checklist de Requisitos Técnico para Conversão de Algarismos Romanos em
            Inteiro:

1. Requisitos Funcionais
1.1. Entrada: string representando número romano, case-insensitive (ex: I, vXx).
1.2. Saída: inteiro correspondente ao valor romano (ex: "XIV" → 14).
1.3. Intervalo suportado: de 1 até 3999.

2. Regras de Negócio e Validações
2.1. Mapeamento de símbolos: I=1, V=5, X=10, L=50, C=100, D=500, M=1000.
2.2. Validação de formato:
• Não podem ocorrer mais de três símbolos repetidos consecutivamente (ex: "IIII" é
inválido).
• Somente pares permitidos de subtração: I antes de V/X; X antes de L/C; C antes de D/M.
2.3. Caso a entrada não respeite o padrão romano ou esteja fora de intervalo, a função
deve lançar uma exceção (ex: InvalidRomanNumeralError).

3. Interface da Função
3.1. Assinatura: int roman_to_int(string roman)
3.2. Aceitar null/empty string? Deve lançar exceção de entrada inválida.

4. Comportamento em Casos de Erro
4.1. String nula ou vazia → InvalidRomanNumeralError.
4.2. Símbolos não romanos presentes → InvalidRomanNumeralError.
4.3. Formato romano incorreto → InvalidRomanNumeralError.
4.4. Resultado fora do intervalo 1–3999 → OutOfRangeError.

5. Testes Unitários (TDD)
5.1. Casos básicos: "I"→1, "V"→5, "X"→10.
5.2. Casos compostos sem subtração: "III"→3, "VIII"→8, "XXVII"→27.
5.3. Casos com subtração: "IV"→4, "IX"→9, "XL"→40, "CM"→900.
5.4. Casos limites: "I"→1, "MMMCMXCIX"→3999.
5.5. Entradas inválidas:
• Repetição excessiva: "IIII".
• Símbolo inválido: "ABCD".
• Subtração não permitida: "IL".
• Resultado >3999: "MMMM".
• String vazia ou null.

6. Qualidade de Código
6.1. Sem variáveis globais.
6.2. Função pura, sem efeitos colaterais.
6.3. Documentação de cada função.

7. Performance e Limites
7.1. Tempo de execução linear no tamanho da string (O(n)).
7.2. Memória adicional constante (O(1)).

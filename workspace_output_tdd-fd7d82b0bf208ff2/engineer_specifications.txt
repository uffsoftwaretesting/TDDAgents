# Especificação Técnica: Conversor de Algarismos Romanos

## 1. Visão Geral do Sistema  
O sistema recebe uma string representando um número em algarismos romanos (case-insensitive) e retorna seu valor inteiro correspondente, suportando valores de 1 a 3999. Entradas inválidas ou fora do padrão geram exceções específicas.

## 2. Estruturas de Dados e Interfaces  

Entidades e Tipos  
- RomanSymbols: mapeamento de caracteres para valores inteiros  
  • I → 1  
  • V → 5  
  • X → 10  
  • L → 50  
  • C → 100  
  • D → 500  
  • M → 1000  

Exceções  
- InvalidRomanNumeralError: sinaliza formato inválido, caracteres não romanos, strings nulas ou vazias.  
- OutOfRangeError: sinaliza resultado fora do intervalo [1, 3999].

Interface da Função  
- Nome: roman_to_int  
- Assinatura: roman_to_int(roman: str) → int  
- Contrato:  
  • Entrada: string não-nula, não-vazia, contendo apenas símbolos romanos válidos, em qualquer combinação de maiúsculas/minúsculas.  
  • Saída: inteiro no intervalo [1, 3999] ou lança uma das exceções declaradas.  

Fluxo de Integração  
1. Cliente chama roman_to_int.  
2. Módulo realiza normalização (uppercase), validações, conversão e retorna valor ou lança exceção.  

## 3. Casos de Borda e Validações (Edge Cases)  

1. Entrada nula ou vazia  
   - Ação: lançar InvalidRomanNumeralError.  
2. Caracteres não romanos (ex.: “ABCD”, dígitos, símbolos especiais)  
   - Ação: lançar InvalidRomanNumeralError.  
3. Repetição excessiva de um símbolo  
   - Mais de três repetições consecutivas de I, X, C ou M → InvalidRomanNumeralError.  
   - Mais de uma repetição de V, L ou D → InvalidRomanNumeralError.  
4. Subtrações inválidas  
   - Permitidas apenas: I antes de V/X; X antes de L/C; C antes de D/M.  
   - Qualquer outro par (ex.: “IL”, “XD”) → InvalidRomanNumeralError.  
5. Ordem dos símbolos  
   - Caso o valor resultante não corresponda ao somatório/subtração padrão de algarismos romanos → InvalidRomanNumeralError.  
6. Resultado fora de 1–3999 (ex.: “MMMM”, valor ≥4000 ou valor 0)  
   - Ação: lançar OutOfRangeError.  

## 4. Contexto Técnico  
- Linguagem-alvo: Python 3.8+  
- Paradigma: programação funcional/pura (função sem efeitos colaterais).  
- Sensibilidade a maiúsculas/minúsculas: case-insensitive (normalizar para uppercase antes de processar).  
- Desempenho esperado:  
  • Tempo de execução O(n), sendo n o comprimento da string de entrada.  
  • Uso de memória adicional constante O(1).  
- Documentação: cada função ou componente deve conter docstring clara descrevendo contrato, parâmetros, retorno e exceções.  
- Tratamento de erros: usar exceções customizadas definidas neste escopo, sem dependências de frameworks externos.

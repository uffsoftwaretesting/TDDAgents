[Usuário]: Como engenheiro de software com foco em computação científica, quero
           desenvolver uma função em Python chamada rk4_classico que resolva um Problema
           de Valor Inicial (PVI) de uma Equação Diferencial Ordinária (EDO) utilizando
           o método clássico de Runge-Kutta de 4ª ordem. A rotina deve ser projetada
           como o motor principal de uma biblioteca matemática de alta performance. Os
           parâmetros devem ser estritamente tipados: a função da EDO f(t,y) injetada
           como um Callable nativo (isento de efeitos colaterais), as condições iniciais
           t0  ​ e y0​, o tempo final t_final​ e o tamanho do passo h.
[Analista]: Para definirmos requisitos técnicos e testáveis mais precisos, poderia
            esclarecer por favor:

1. Suporte a EDOs escalares vs. sistemas vetoriais: a função deve aceitar apenas y e f
como floats (EDO escalar) ou também vetores (por exemplo numpy.ndarray) para sistemas de
equações?
2. Formato de saída esperado: retornar apenas y(t_final) ou toda a trajetória de solução
(arrays de t e y em cada passo)?
3. Ajuste de passo final: se (t_final – t0) não for múltiplo exato de h, você prefere
que a rotina ajuste o último passo para alcançar t_final ou lance um erro de validação
de parâmetro?

Após esses esclarecimentos, gerarei o checklist de requisitos.

[Usuário]: A EDO é sempre escalar. O formato de retorno deve ser o valor final. Ajuste o
           passo   conforme necessário.
[Analista]: Checklist de Requisitos Técnico para rk4_classico (EDO escalar, retorna
            y(t_final), ajusta último passo)

1. Definição de assinatura e tipos
- Função rk4_classico(f: Callable[[float, float], float],
t0: float,
y0: float,
t_final: float,
h: float) -> float
- Docstring descrevendo parâmetros e comportamento.

2. Validação de parâmetros de entrada
- f deve ser um Callable sem efeitos colaterais que recebe (t: float, y: float) e
retorna float.
- t0, y0, t_final, h devem ser floats.
- h > 0, t_final > t0: lançar ValueError em caso de violação.

3. Lógica de ajuste de passo final
- Calcular número de passos n = floor((t_final - t0) / h).
- Determinar h_last = (t_final - t0) - n * h; se h_last > 0, executá-lo como último
passo.

4. Algoritmo RK4 (laço principal)
- Inicializar t = t0, y = y0.
- Para cada passo i de 1 a n:
* k1 = h * f(t, y)
* k2 = h * f(t + h/2, y + k1/2)
* k3 = h * f(t + h/2, y + k2/2)
* k4 = h * f(t + h, y + k3)
* y += (k1 + 2*k2 + 2*k3 + k4) / 6
* t += h
- Se h_last > 0, repetir com h = h_last para ajustar t até t_final.

5. Retorno
- Retornar apenas y (float) correspondente a y(t_final).

6. Robustez e performance
- Não acumular arrays de resultados (somente variáveis escalares).
- Evitar importações desnecessárias; depender apenas de Python padrão.
- Minimizar overhead de chamadas de função.

7. Tratamento de erros e exceções
- ValueError com mensagens claras em: h <= 0, t_final <= t0.
- Propagar exceções de f(t,y) sem silenciá-las.

8. Testes unitários (TDD)
- Caso trivial dy/dt = 0, y0 constante ⇒ y(t_final) == y0.
- Crescimento exponencial dy/dt = a*y, compare com y0 * exp(a*(t_final-t0)).
- Teste de ajuste de passo: escolher (t_final - t0)/h não inteiro.
- Parâmetros inválidos (h <= 0, t_final <= t0) devem lançar ValueError.
- Teste de estabilidade em Y e T com valores extremos (floats grandes).

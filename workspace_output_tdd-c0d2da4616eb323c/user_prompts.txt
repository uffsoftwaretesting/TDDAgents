[Analista]: Checklist de Requisitos Técnico para a função integracao_trapezio:

1. Assinatura e Documentação
• Função: integracao_trapezio(
f: Callable[[float], float],
a: float,
b: float,
N: Optional[int] = None,
tol: Optional[float] = None
) -> float
• Docstring explicando: parâmetros, comportamento adaptativo (quando tol é fornecida) e
composto (quando tol é None).

2. Validação de Parâmetros (lançar TypeError ou ValueError)
• f deve ser callable; ao chamar f(x) retorna float.
• a, b devem ser floats e satisfazer a < b.
• Se tol != None:
– tol deve ser float > 0.
– N, mesmo que fornecido, é ignorado.
• Se tol é None:
– N deve ser int > 0.
• Se tol é None e N é None: lançar ValueError("É preciso fornecer N ou tol").

3. Comportamento de Integração
3.1. Integração Composta (tol = None)
– Calcular h = (b – a) / N
– Calcular soma = 0.5 * (f(a) + f(b)) + Σ f(a + i⋅h) para i = 1…N–1
– Retornar h * soma
3.2. Integração Adaptativa (tol fornecida)
– Iniciar N₀ (ex: N₀ = 1)
– Calcular T₀ usando Regra Composta
– Para k = 1, 2, …:
• Nₖ = 2·Nₖ₋₁
• Calcular Tₖ (Regra Composta com Nₖ)
• Estimativa de erro = |Tₖ – Tₖ₋₁| / 3
• Se erro ≤ tol, retornar Tₖ
– Limitar número máximo de iterações para evitar loop infinito (ex: 20 iterações)

4. Implementação
• Apenas operações escalares (chamadas f(x) → float); sem vetorização.
• Uso de laços for; variáveis locais para acumular soma.

5. Tratamento de Exceções e Mensagens
• Mensagens claras em cada TypeError/ValueError (ex: "tol deve ser float positivo", "N
deve ser int positivo", "a deve ser menor que b").

6. Critérios de Teste (TDD)
• Caso linear: f(x)=mx+c; N=1; tol=None; resultado exato.
• Caso polinomial: f(x)=x²; N=100; tol=None; comparar com (b³–a³)/3.
• Adaptativo: f(x)=sin(x) em [0, π]; tol=1e-6; resultado ≈ 2.
• a == b → retorna 0 imediatamente.
• Parâmetros inválidos:
– N ≤ 0 ou não-int → ValueError
– tol ≤ 0 → ValueError
– ambos None → ValueError
• Ambos fornecidos (N e tol) → usa adaptativo (tol), ignora N.

REQUISITOS ENVIADOS PELO USUÁRIO
================================================================================
[Usuário]: Aja como um engenheiro de software especializado em Python. O caso de uso
           consiste em converter números representados como strings em algarismos
           romanos para seus equivalentes inteiros. A tarefa é projetar e implementar
           uma função em Python puro, sem uso de bibliotecas externas, que receba uma
           única string como entrada e retorne um inteiro como saída. A saída deve ser
           um número inteiro correspondente ao valor romano válido ou lançar uma exceção
           do tipo ValueError em caso de entrada inválida. O método deve implementar os
           símbolos básicos I, V, X, L, C, D, M e respeitar as regras de subtração IV,
           IX, XL, XC, CD, CM, além de tratar a entrada de forma case-insensitive. As
           premissas incluem suporte apenas para valores entre 1 e 3999, rejeição de
           strings vazias, caracteres inválidos, sequências malformadas, repetições
           ilegais e combinações inválidas como IC, IL e VX. Os testes devem incluir
           casos válidos (por exemplo, III, IX, LVIII, MCMXCIV), inválidos (como IC,
           XXXX, VV, string vazia) e casos de borda (como I e MMMCMXCIX). Não devem ser
           implementados testes de documentação, docstrings ou types.
[Analista]: Checklist de Requisitos Técnico para função roman_to_int(s: str) -> int:

1. Definição de Interface:
- Assinatura: roman_to_int(s: str) -> int
- Input: string ‘s’ (case-insensitive)
- Output: inteiro no intervalo [1, 3999]
- Exceção em caso de entrada inválida: ValueError

2. Mapeamento de Símbolos:
- I=1, V=5, X=10, L=50, C=100, D=500, M=1000

3. Regras de Subtração Válidas:
- I antes de V ou X
- X antes de L ou C
- C antes de D ou M
- Qualquer outra combinação de subtração deve causar ValueError

4. Regras de Repetição:
- I, X, C, M no máximo 3 vezes consecutivas
- V, L, D não podem se repetir consecutivamente

5. Validação da String de Entrada:
- Não aceitar string vazia
- Apenas caracteres I, V, X, L, C, D, M em qualquer caixa
- Detectar e rejeitar combinações ilegais (IC, IL, VX, etc.)

6. Lógica de Conversão (Exemplo de algoritmo):
- Percorrer a string de esquerda para direita
- Para cada símbolo, comparar seu valor com o valor do próximo símbolo
• Se >= próximo, somar seu valor ao total
• Se < próximo, subtrair seu valor do total
- Ao final, verificar se total está entre 1 e 3999

7. Tratamento de Erros:
- ValueError para:
• String vazia
• Caracteres inválidos
• Sequências de repetição ilegais
• Combinações de subtração inválidas
• Resultado fora do intervalo 1–3999

8. Casos de Teste (TDD):
8.1 Válidos:
- “III” → 3
- “IV” → 4
- “IX” → 9
- “LVIII” → 58
- “MCMXCIV” → 1994
- “mmmxmxcix” (case-insensitive) → 3999
8.2 Inválidos (ValueError):
- string vazia
- caracteres não romanos (“ABCD”)
- repetições ilegais (“XXXX”, “VV”)
- subtrações inválidas (“IC”, “IL”, “VX”)
8.3 Casos de Borda:
- “I” → 1
- “MMMCMXCIX” → 3999

9. Critérios de Aceitação:
- Todos os testes definidos em 8.1–8.3 devem passar com sucesso
- Cobertura completa de todos os caminhos de erro e sucesso

# Especificação Técnica: Conversor de Numerais Romanos

## 1. Visão Geral do Sistema
Implementar uma função em Python puro que converta uma string representando um número em algarismos romanos no seu valor inteiro correspondente (1–3999). Em caso de entrada inválida (tipo, formato ou valor fora de domínio), a função deve lançar exceções apropriadas (`TypeError` ou `ValueError`).

## 2. Estruturas de Dados e Interfaces

### Função Pública
- **assinatura**: `roman_to_int(roman: str) -> int`
- **entrada**:  
  - `roman`: string (case-insensitive) contendo símbolos romanos.
- **saída**:  
  - inteiro no intervalo [1, 3999].
- **exceções**:  
  - `TypeError` se `roman` não for do tipo `str`.  
  - `ValueError` em qualquer validação de formato, conteúdo ou intervalo.

### Entidades Auxiliares
- Dicionário de valores:
  - ROMAN_VALUES:  
    ```
    {
      'I': 1,
      'V': 5,
      'X': 10,
      'L': 50,
      'C': 100,
      'D': 500,
      'M': 1000
    }
    ```
- Conjunto de pares de subtração válidos:
  - VALID_SUBTRACTIVE_PAIRS = { "IV", "IX", "XL", "XC", "CD", "CM" }
- Constantes de domínio:
  - MIN_VALUE = 1  
  - MAX_VALUE = 3999

### Fluxo de Integração entre Componentes
1. **Validação de tipo**  
2. **Normalização** → uppercase  
3. **Validação de caracteres**  
4. **Verificação de repetição e regras de subtração**  
5. **Parsing** usando ROMAN_VALUES e lógica de soma/subtração  
6. **Verificação de faixa**  
7. **Retorno** ou lançamento de exceção

## 3. Casos de Borda e Validações (Edge Cases)

1. Validação de Tipo  
   - Entrada não-`str` (ex.: `123`, `None`, `[]`) → lança `TypeError`.
2. String Vazia  
   - `len(roman) == 0` → lança `ValueError`.
3. Caracteres Inválidos  
   - Qualquer caractere fora de {I, V, X, L, C, D, M} → `ValueError`.
4. Regras de Repetição  
   - I, X, C, M repetidos mais de 3 vezes consecutivas (ex.: “IIII”) → `ValueError`.  
   - V, L, D repetidos consecutivamente (ex.: “VV”) → `ValueError`.
5. Regras de Subtração  
   - Apenas pares em VALID_SUBTRACTIVE_PAIRS permitidos (IV, IX, XL, XC, CD, CM).  
   - Nenhuma outra forma de subtração (ex.: “IIV”, “XXL”, “IL”, “IC”) → `ValueError`.
6. Combinações Ilegais  
   - Sequências como IC, IL, ID, IM, VX, VL, VC, VD, VM, XD, XM → `ValueError`.
7. Lógica de Parsing  
   - Para cada símbolo, comparar seu valor com o próximo:  
     - Se valor_atual < valor_próximo e formarem par em VALID_SUBTRACTIVE_PAIRS → subtrair.  
     - Se valor_atual < valor_próximo e **não** estiver em VALID_SUBTRACTIVE_PAIRS → `ValueError`.  
     - Caso contrário, somar.
8. Verificação de Faixa Pós-Parsing  
   - Resultado < MIN_VALUE ou > MAX_VALUE → `ValueError`.

### Exemplos de Casos de Teste

- Válidos:  
  • “III” → 3  
  • “IV” → 4  
  • “IX” → 9  
  • “LVIII” → 58  
  • “MCMXCIV” → 1994  
  • case-insensitive: “mcmxciv” → 1994  
- Inválidos:  
  • string vazia (“”)  
  • caracteres inválidos (“A”, “B1”)  
  • repetições ilegais (“XXXX”, “VV”, “IIV”)  
  • combinações proibidas (“IL”, “IC”, “XM”)  
  • fora de faixa (“MMMM” → 4000)  
- Borda:  
  • “I” → 1  
  • “MMMCMXCIX” → 3999  
- Tipo errado:  
  • `123`, `None`, `[]` → `TypeError`

## 4. Contexto Técnico
- Linguagem-alvo: Python 3.x puro, sem bibliotecas externas.  
- Paradigma: imperativo/funcional, implementação numa única função.  
- Sensibilidade de caso: insensível (converter tudo para uppercase).  
- Exceções padronizadas para falhas de entrada e domínio.  
- Suporte unicamente ao intervalo 1–3999.

## 5. Dependências Base (Core Dependencies)
- Python 3.x (built-in)  
- pytest (para a suíte de testes)  
- ferramentas padrão de linting e CI (opcional)

# Especificação Técnica: adams_bashforth_3

## 1. Visão Geral do Sistema
A função `adams_bashforth_3` realiza a integração numérica de um problema de valor inicial para EDO escalar de primeira ordem usando o método explícito de Adams–Bashforth de terceira ordem. Para iniciar o método de múltiplos passos, os dois primeiros pontos são gerados por Runge–Kutta de quarta ordem. A malha temporal é construída de forma a garantir que o último ponto coincida exatamente com `t_final`, ajustando dinamicamente o tamanho do último passo quando necessário. O resultado final é um único valor `float` que estima `y(t_final)`.

## 2. Estruturas de Dados e Interfaces

### Assinatura da Função
A interface pública é:
```python
def adams_bashforth_3(
    f: Callable[[float, float], float],
    t0: float,
    y0: float,
    t_final: float,
    h: float
) -> float
```

### Parâmetros de Entrada
- `f`: função pura `f(t, y) -> float` que calcula dy/dt sem efeitos colaterais.
- `t0`: instante inicial, tipo `float`.
- `y0`: valor inicial y(t0), tipo `float`.
- `t_final`: instante final de integração, tipo `float`, deve satisfazer `t_final >= t0`.
- `h`: passo nominal de integração, tipo `float`, deve satisfazer `h > 0`.

### Valor de Retorno
- Resultado `float` correspondente a `y(t_final)`. Não há retorno de histórico ou estruturas auxiliares.

### Exceções
- `TypeError` para tipos inválidos de parâmetros.
- `ValueError` para `h <= 0`, `t_final < t0` ou intervalos degenerados.
- `RuntimeError` para falha em `f` ou erro interno de avaliação das derivadas.

## 3. Casos de Borda e Validações (Edge Cases)
- **`f` não é chamável**: lançar `TypeError("f deve ser uma função chamável")`.
- **Parâmetros não são `float`**: lançar `TypeError("t0, y0, t_final e h devem ser floats")`.
- **`h <= 0`**: lançar `ValueError("h deve ser maior que zero")`.
- **`t_final < t0`**: lançar `ValueError("t_final deve ser maior ou igual a t0")`.
- **Intervalo zero (`t_final == t0`)**: retornar `y0` imediatamente sem chamadas a `f`.
- **`h` maior que interval total**: o primeiro e único passo será `dt = t_final - t0`; aplicar RK4 para obter y1, y2 só se for possível e depois usar AB3 com histórico apropriado. Caso não haja três pontos, lançar `ValueError("passos insuficientes para AB3")`.
- **`(t_final - t0)` não divisível por `h`**: o último passo é truncado para `dt_last = t_final - t_n`; aplicar AB3 com `dt_last`.
- **Exceções em `f`**: capturar e relançar como `RuntimeError("erro ao avaliar f: " + mensagem_original)`.
- **Divisão por zero interna**: detectada e convertida em `ValueError("erro numérico: divisão por zero")`.

## 4. Contexto Técnico
- Linguagem-alvo: Python 3.8+.
- Paradigma: programação funcional em escopo local (nenhuma variável global ou estado externo).
- Precisão: operações em `float` padrão IEEE 754, garantindo reprodutibilidade bit-a-bit.
- Determinismo: ausência de RNG ou efeitos colaterais externos.
- Não usar estruturas de dados além de variáveis escalares locais e listas / tuplas para manter histórico interno das últimas três avaliações.

PLANO DE SUB-REQUISITOS TDD
================================================================================
1. FASE 0 - SETUP AMBIENTE: Instalar as dependências base (FastAPI, Uvicorn, python-dotenv, validate-docbr, Pydantic, pytest, pytest-cov, docker, docker-compose), inicializar repositório Git, criar a estrutura de diretórios em src/ (core/, domain/, application/, infrastructure/, interface/) e tests/, adicionar __init__.py em cada pacote e criar core/config.py para carregar variáveis de .env via python-dotenv.
2. FASE 1 - DOMAIN: Criar domain/entities/cpf.py com a classe CPF (raw e normalized), implementando trim, remoção de máscara e validações de domínio (11 dígitos, não todos iguais); definir domain/errors.py para exceções de domínio. Escrever testes unitários com pytest para: strings vazias, remoção de caracteres não numéricos, comprimento incorreto, dígitos repetidos, casos de sucesso de normalização.
3. FASE 2 - INFRASTRUCTURE: Definir interface CPFValidator em infrastructure/validators/base.py (método is_valid(cpf: str) -> bool) e implementar LibraryCPFValidator em infrastructure/validators/validate_docbr.py usando a biblioteca validate-docbr (ou python-cpf). Escrever testes unitários que substituam o adaptador real por um stub/mock e validem comportamento de retorno em cenários válidos e inválidos.
4. FASE 3 - APPLICATION: Criar application/dto/validation_result.py com ValidationResult e application/use_cases/validate_cpf.py com ValidateCPFUseCase.execute(raw_cpf: str) -> ValidationResult. Implementar fluxo: instanciação de CPF, captura de erros de domínio, chamada a CPFValidator.is_valid, formatação de saída em máscara XXX.XXX.XXX-XX. Escrever testes unitários cobrindo: CPF válido, CPF inválido por domínio, CPF inválido por dígito verificador, formatação correta.
5. FASE 4 - INTERFACE: Em interface/schemas.py definir CPFRequestSchema e CPFResponseSchema com Pydantic; em interface/routes.py criar rota POST /validate-cpf que recebe CPFRequestSchema, invoca ValidateCPFUseCase e retorna CPFResponseSchema com status 200 ou 422 automático do Pydantic. Escrever testes com FastAPI TestClient cobrindo: payload ausente/nulo → 422, extra fields descartados, empty string → valid:false, formatos com/sem máscara, espaços em branco, cenários válidos e inválidos.
6. FASE 5 - CONFIGURAÇÃO DO APP: Em core/app.py montar instância FastAPI, incluir router em /validate-cpf, carregar config de core/config.py, configurar logging básico e exception handlers para erros de domínio retornando valid:false com status 200. Escrever teste de integração leve importando app e testando handlers personalizados.
7. FASE 6 - CONTAINERIZAÇÃO: Criar Dockerfile multi-stage usando python:3.x-slim, instalar dependências, copiar código, expor porta 8000 e definir entrypoint uvicorn core.app:app. Adicionar docker-compose.yml para orquestrar serviços (app e variáveis de ambiente). Validar com um teste de smoke: build da imagem e resposta 200 em /validate-cpf.
8. FASE 7 - CI/CD: Criar workflow GitHub Actions em .github/workflows/ci.yml com steps: checkout, setup Python, instalar dependências, executar pytest com cobertura, executar lint (flake8/black opcional), build Docker image e validar healthcheck. Configurar aprovação de PR condicionada a cobertura mínima de 90% e build bem-sucedido.

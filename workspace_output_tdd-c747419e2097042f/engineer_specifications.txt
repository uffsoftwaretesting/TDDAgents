# Especificação Técnica: CPF Validation API

## 1. Visão Geral do Sistema
Uma API RESTful em Python usando FastAPI organizada segundo os princípios de Clean Architecture. Expõe o endpoint POST /validate-cpf que recebe um JSON com campo cpf (string) e retorna se o CPF é válido ou não. A solução terá camadas separadas (domain, application, infrastructure, presentation/interfaces), injeção de dependência, testes TDD espelhados em pytest, configuração Docker (desenvolvimento e produção) e pipeline CI com GitHub Actions.

## 2. Estruturas de Dados e Interfaces

### 2.1 Domain Layer  
Entidade e regras puras sem dependências externas:
- Entidade CPF  
  - Propriedades imutáveis:  
    • raw_value: str  
    • normalized_value: str  (apenas dígitos)  
  - Métodos (privados ou internos):  
    • _remove_mask() → str  
    • _validate_length() → void  (deve lançar CpfInvalidError se não forem 11 dígitos)  
    • _validate_sequence() → void  (rejeita sequências de dígitos idênticos)  
    • _validate_check_digits() → void  (cálculo e verificação dos dígitos verificadores)  
- Exceção de domínio:  
  - class CpfInvalidError(Exception)

### 2.2 Application Layer  
Caso de uso e interfaces:
- Interface (protocolo) ValidateCpfUseCase  
  - Método: execute(cpf_value: str) → bool  
- Implementação concreta recebe instância de CPFValidatorAdapter e:  
  1. Cria CPF(raw_value)  
  2. Retorna True/False baseado em sucesso ou captura de CpfInvalidError

### 2.3 Infrastructure Layer  
Adaptação de biblioteca externa:
- Interface (protocolo) CPFValidatorAdapter  
  - Método: is_valid(cpf: str) → bool  
- Implementação concreta usando validate-docbr ou python-cpf  
  - Converte exceções da biblioteca em CpfInvalidError ou retorna False

### 2.4 Presentation/Interfaces Layer  
FastAPI + Pydantic:
- Schemas Pydantic:  
  - ValidateCpfRequest  
    • cpf: str  
  - ValidateCpfResponse  
    • valid: bool  
- Controller FastAPI:  
  - Rota: POST /validate-cpf  
  - Parâmetros:  
    • body: ValidateCpfRequest  
    • use_case: ValidateCpfUseCase = Depends(get_validate_cpf_use_case)  
  - Fluxo:  
    1. Chama use_case.execute(request.cpf)  
    2. Retorna 200 com ValidateCpfResponse(valid=resultado)  
  - Tratamento de payload inválido: 422 automático pelo Pydantic

### 2.5 Configuração de Ambiente  
- Loader de variáveis de ambiente: classe Settings (pydantic.BaseSettings)  
- Arquivo .env na raiz com variáveis de configuração (ex: LOG_LEVEL, ENVIRONMENT)

## 3. Casos de Borda e Validações (Edge Cases)
- Campo “cpf” ausente: HTTP 422  
- Campo “cpf” nulo: HTTP 422  
- Campo “cpf” vazio (“”): considerado inválido no domínio → retorna 200 { "valid": false }  
- CPF com caracteres não numéricos ou símbolos além de máscara (. e -): máscara removida; símbolos inesperados (> 11 dígitos ou letras) → 200 { "valid": false }  
- CPF com menos de 11 dígitos após remover máscara: 200 { "valid": false }  
- CPF com mais de 11 dígitos após remover máscara: 200 { "valid": false }  
- Sequência de 11 dígitos idênticos (ex: “11111111111”): 200 { "valid": false }  
- Dígitos verificadores incorretos: 200 { "valid": false }  
- CPF válido com máscara (“123.456.789-09”): 200 { "valid": true }  
- CPF válido sem máscara (“12345678909”): 200 { "valid": true }  

## 4. Contexto Técnico
- Linguagem: Python >=3.9  
- Framework web: FastAPI  
- Paralelismo: Uvicorn + ASGI  
- Paradigma: Clean Architecture (separação de camadas, baixo acoplamento, alta coesão)  
- Tipagem estática: mypy compatível  
- Configuração de logging centralizado e tratamento global de exceções  
- Autodocumentação: OpenAPI/Swagger gerada pelo FastAPI  
- Arquitetura de testes: TDD com pytest; estrutura de diretórios espelhada  
- Containerização: Docker multi-stage; hot-reload em dev; volume mount

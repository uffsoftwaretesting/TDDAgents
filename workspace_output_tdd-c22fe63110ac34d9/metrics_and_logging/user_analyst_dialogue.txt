[Usuário]: Crie um backend em FastAPI que disponibilize uma API para converter texto
           Markdown em HTML. O sistema deve expor um endpoint que receba conteúdo em
           Markdown via requisição HTTP e retorne o HTML correspondente, utilizando uma
           biblioteca adequada para a conversão. Organize o projeto seguindo boas
           práticas de desenvolvimento, separando configurações, schemas, serviços e
           rotas. Implemente validação dos dados de entrada, tratamento de erros e
           respostas padronizadas. Todas as configurações devem ser carregadas por
           variáveis de ambiente utilizando um arquivo .env, fornecendo também um
           arquivo .env.example com exemplos das variáveis necessárias para configuração
           do projeto. Inclua todas as dependências necessárias em um arquivo
           requirements.txt, especificando as bibliotecas utilizadas para execução da
           aplicação.
[Analista]: Checklist de Requisitos Técnico para API de Conversão Markdown → HTML:

1. Estrutura do Projeto
1.1. Diretórios principais:
• app/
– main.py
– config/
– schemas/
– services/
– routes/
• tests/
• .env
• .env.example
• requirements.txt
• README.md
1.2. Seguir padrões de import absolute e agrupar módulos por responsabilidade.

2. Configuração e Variáveis de Ambiente
2.1. Criar arquivo .env com variáveis:
• APP_NAME (ex: "MarkdownConverter")
• HOST (ex: "0.0.0.0")
• PORT (ex: "8000")
• LOG_LEVEL (ex: "INFO")
2.2. Fornecer .env.example com valores de exemplo.
2.3. Implementar carregamento via pydantic.BaseSettings em config/settings.py.

3. Dependências
3.1. Gerar requirements.txt com versões fixas de:
• fastapi
• uvicorn
• pydantic
• python-dotenv
• markdown (ou markdown2)
3.2. Incluir instruções de instalação no README.md.

4. Schemas de Dados (schemas/markdown.py)
4.1. InputModel:
• campo markdown: str (não vazio, máximo 10000 caracteres)
4.2. OutputModel:
• campo html: str
• status: Literal['success']
4.3. ErrorModel padrão para respostas de erro:
• status: Literal['error']
• message: str
• details: Optional[Any]

5. Serviço de Conversão (services/converter.py)
5.1. Função convert_markdown_to_html(markdown_text: str) -> str:
• Utilizar biblioteca python-markdown ou markdown2
• Testar conversão correta de headings, listas, links, imagens, código inline/blocos de
código.
• Lidar com strings vazias retornando string vazia.

6. Rotas e Endpoints (routes/markdown.py)
6.1. Definir APIRouter com prefix '/markdown' e tag 'Markdown'.
6.2. Endpoint POST '/convert':
• Recebe InputModel em JSON
• Chama serviço convert_markdown_to_html
• Retorna OutputModel com HTML convertido
• Respostas esperadas:
– 200: conversão bem-sucedida
– 422: validação de payload
– 500: erro interno de conversão

7. Tratamento de Erros e Respostas Padronizadas
7.1. Utilizar exceções HTTPException do FastAPI.
7.2. Implementar exceção genérica para erros de conversão.
7.3. Retornar ErrorModel em JSON com status, message e details (se aplicável).

8. Validação e Respostas HTTP
8.1. Garantir retorno de status code corretos:
• 200 OK → sucesso
• 400 Bad Request → payload inválido ou vazio
• 500 Internal Server Error → falha inesperada
8.2. Mensagens de erro descritivas para facilitar debug.

9. Carregamento e Execução da Aplicação (main.py)
9.1. Instanciar FastAPI com título e versão.
9.2. Incluir middleware de logging (opcional).
9.3. Incluir rotas definidas.
9.4. Configurar host e porta via settings carregados do .env.

10. Testes Automatizados (TDD)
10.1. test_services/test_converter.py:
• cenários: markdown simples, headings, listas, links, imagens, código.
• string vazia → string vazia.
10.2. test_routes/test_markdown_endpoint.py:
• sucesso 200 com HTML válido
• 422 payload sem campo ‘markdown’
• 422 markdown nulo ou tipo errado
• simular erro interno → 500

11. Documentação e README
11.1. Explicar como configurar .env e instalar dependências.
11.2. Exemplos de requisição via curl ou HTTPie.
11.3. Como executar testes.

PLANO DE SUB-REQUISITOS TDD
================================================================================
1. FASE 0 - SETUP: Inicializar o projeto na sandbox criando virtualenv Python 3.9+, adicionar pyproject.toml com seção [tool.poetry] ou equivalente, configurar requirements-dev.txt com pytest e mypy, criar estrutura de diretórios src/ e tests/ e arquivos vazios src/rk2_ponto_medio.py e tests/test_rk2_ponto_medio.py
2. FASE 1 - ASSINATURA & STUB: No tests/test_rk2_ponto_medio.py, escrever testes que importem rk2_ponto_medio e verifiquem que é uma função com a assinatura correta (tipos f: Callable[[float,float],float], t0: float, y0: float, t_final: float, h: float). Executar pytest para ver testes falhando, depois implementar em src/rk2_ponto_medio.py um stub def rk2_ponto_medio(...): pass
3. FASE 2 - CASO TRIVIAL: Criar teste que chame rk2_ponto_medio com t_final == t0 usando uma f que levanta exceção se executada; validar que retorna y0 sem chamar f. Executar pytest para ver falha, implementar lógica no stub para detectar t_final==t0 e retornar y0 imediatamente
4. FASE 3 - VALIDAÇÃO DE PARÂMETROS: Escrever testes que passem valores inválidos (f não-callable, t0/y0/t_final/h não-float, h≤0, t_final<t0) e esperem TypeError ou ValueError conforme especificado. Validar falhas dos testes e implementar checagens no início de rk2_ponto_medio levantando as exceções corretas
5. FASE 4 - LOOP RK2 PONTO-MÉDIO: Escrever testes de integração para ODE simples (por ex. f(t,y)=λ com solução y=y0+λ*(t_final−t0)), comparando resultado RK2 ao valor analítico dentro de tolerância. Implementar o loop while t< t_final com ajuste h_i=min(h, t_final−t), cálculos de k1, y_mid, k2 e atualização de y e t
6. FASE 5 - CHECAGEM DE TIPOS INTERMEDIÁRIOS: Adicionar testes que façam f retornar valores não-float em k1 ou k2 e esperem TypeError. Implementar verificações logo após cada chamada de f garantindo que k1 e k2 são floats, caso contrário lançar TypeError
7. FASE 6 - DOCSTRING & TYPE HINTS: Em src/rk2_ponto_medio.py, adicionar docstring estilo NumPy ou Google, aplicar type hints conforme assinatura e rodar mypy para garantir 100% de conformidade sem avisos; ajustar configurações de mypy em pyproject.toml se necessário
8. FASE 7 - CI & QUALITY GATES: Configurar pipeline (ex: GitHub Actions) para executar pytest com coverage, mypy e flake8 em cada push; incluir badge no README e garantir build verde antes de aceitar pull requests
================================================================================

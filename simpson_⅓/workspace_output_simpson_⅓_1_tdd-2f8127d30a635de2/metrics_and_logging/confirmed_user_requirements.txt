           definida, sem qualquer tipo de impressão, log ou efeito colateral; a
           implementação deve seguir rigorosamente a formulação da Regra de Simpson 1/3
           Composta, garantindo a correta discretização do intervalo [a, b] e a

           testes de convergência numérica; utilize NumPy apenas quando apropriado e sem

[Analista]: Checklist de Requisitos Técnico para integracao_simpson_1_3:

1. Interface da Função
• Assinatura: def integracao_simpson_1_3(f: Callable[[float], float], a: float, b:
float, N: int) -> float
• Parâmetros claramente tipados e documentados em docstring (f, a, b, N)
• Retorno: valor float da aproximação da integral

2. Validação de Entrada
• Verificar que f é callable; caso contrário, lançar TypeError
• Verificar que a e b são floats (ou valores numéricos); caso contrário, TypeError
• Verificar que N é inteiro par e N > 0; caso contrário, ValueError com mensagem
descritiva
• Tratar caso a == b: retornar 0.0 sem erro

3. Discretização e Cálculo de h
• Calcular h = (b - a) / N usando operações float
• Garantir determinismo (não usar funções com comportamento não-determinístico)

4. Aplicação da Regra de Simpson 1/3 Composta
• Gerar sequência de pontos x_j = a + j*h para j = 0..N
• Calcular f(x_j) de forma isolada (sem efeitos colaterais)
• Somar f(x_0) + f(x_N)
• Somar 4 * f(x_j) para j ímpar
• Somar 2 * f(x_j) para j par, j ≠ 0, N
• Combinar resultados: integral ≈ h/3 * (soma total)

5. Uso Opcional de NumPy
• Permitir vetorizar f(x_j) somente se gerar ganho mensurável de desempenho
• Garantir que a importação de numpy seja local e opcional, sem complexidade extra

6. Restrições de Ambiente e Imports
• Não manipular PYTHONPATH ou sys.path
• Não usar hacks de caminho (sys.path.append, set PYTHONPATH, export PYTHONPATH)
• Código deve rodar a partir da raiz do projeto sem configuração extra
• Módulo deve residir em src/integracao.py (ou similar) sem scripts auxiliares

7. Boas Práticas de Código
• Seguir PEP8 (linhas ≤ 79 caracteres, nomes legíveis)
• Adicionar docstring explicando a regra, parâmetros, retornos e exceções
• Evitar prints, logs, ou qualquer efeito colateral
• Código claro e legível, com comentários mínimos onde necessário

8. Testabilidade e TDD
• Criar testes unitários que validem casos clássicos:
– ∫_0^1 x^n dx = 1/(n+1) para n = 0, 1, 2
– ∫_0^π sin(x) dx = 2
• Verificar convergência ao dobrar N (erro decai ~O(N⁻⁴))
• Testar falhas de validação (N ímpar, tipos incorretos)
• Testar caso degenerate a == b

9. Consistência e Determinismo
• Garantir que chamadas repetidas com mesmos parâmetros retornem exatamente mesmo float
• Não usar fontes de aleatoriedade ou estados globais
